# خطة إعادة تصميم وتطوير نظام مشاركة الآيات القرآنية كصورة (Quran Share Redesign Plan)

---

## 1. تشخيص الوضع الحالي والعلة الهندسية (Root Cause Diagnosis)

### أسباب المشكلة الحالية (ظهور الصورة بأبعاد تقريبية 616 × 1630 ونسبة طولية غير متوازنة):
1. **الاعتماد على التقاط المعاينة المباشرة لشاشة الهاتف (Screen-bound Capture)**:
   - في الكود الحالي بملف `quran_share_composer_dialog.dart`:
     يتم تمرير مفتاح `_previewKey` إلى ويدجت `QuranShareRenderer` الموجود داخل نافذة منبثقة (`BottomSheet`) داخل `SingleChildScrollView`.
   - يتم أخذ اللقطة عبر:
     ```dart
     final boundary = _previewKey.currentContext?.findRenderObject() as RenderRepaintBoundary?;
     final image = await boundary.toImage(pixelRatio: 3.0);
     ```
   - هذا يعني أن أبعاد الصورة الناتجة **مرتهنة كلياً بعرض شاشة الهاتف الحقيقي** مطروحاً منه هوامش النافذة المنبثقة:
     - على شاشة هاتف عرضها 390px مع هوامش 20px يميناً ويساراً وهوامش داخلية، يصبح العرض المتاح للبطاقة تقريباً 205–220px فقط.
     - عند ضرب هذا العرض في `pixelRatio: 3.0`، ينتج العرض المشوه: `205.33 × 3 ≈ 616 px`!
     - ومع تدفق نصوص الآيات رأسياً في مساحة ضيقة، يتمدد الارتفاع ليصل إلى 543px، والذي عند ضربه في 3 ينتج: `543.33 × 3 ≈ 1630 px`!
2. **الافتقار إلى لوحة رسم مستقلة (Resolution-Independent Canvas)**:
   - لا توجد أبعاد تصميمية أساسية ثابتة (مثل 1080px).
   - المظهر البصري الحالي هو بطاقة تطبيق واجهة مستخدم (بطاقة بزوايا دائرية عادية `BorderRadius.circular(22)`، زر بيضاوي كلاسيكي للعنوان، وفواصل رمادية بسيطة) ولا يرقى إلى مظهر صفحة مصحف أو مخطوطة إسلامية عريقة.

## 2. الرؤية التصميمية الجديدة (Manuscript-Inspired Visual Design)

الهدف هو تحويل الصورة من "سكرين شوت لبطاقة داخل تطبيق" إلى **"لوحة مصحف ومخطوطة إسلامية رقمية فاخرة مُعدة خصيصاً للمشاركة والتداول"**:

| العنصر | المواصفات التصميمية |
| :--- | :--- |
| **الخلفية (Background)** | ورق المصحف السمني الدافئ العريق (`#F6F0E4`) بملمس هادئ ونظيف بدون تدرجات لونية حادة أو شوائب. |
| **الإطار الإسلامي (Border)** | إطار مصحفي مزدوج مذهب: خط خارجي دقيق (`#B58A4A`)، ممر فراغي خفيف، خط وسطي رئيسي مذهب، خط داخلي أرفع بلون رملي هادئ (`#D8C5A5`). |
| **الزخارف الركنية (Corner Ornaments)** | شرافات وزخارف ركنية إسلامية رقيقة ومتناظرة (Arabesque Corner Motifs) في الأركان الأربعة متناسقة نسبياً مع أبعاد اللوحة دون تداخل مع النص. |
| **عنوان السورة (Header)** | ترويسة مصحفية كلاسيكية (مثل `سُورَةُ آلِ عِمْرَان`) بخط عريق (`AmiriQuran` / `UthmanicHafs`) محاطة بحليتين زخرفيتين مذهبتين متناظرتين (أجنحة شرافية) بدون أزرار أو حواف دائرية حديثة. |
| **نص الآيات (Quran Text)** | تدفق قرآني متصل وموحد بخط مصحف المدينة `UthmanicHafs` الأصيل، متباعد الأسطر بارتياح (`height: 2.15–2.25`)، مع حجم خط متسق لجميع الأسطر دون تصغير سطري (`no per-line FittedBox`). |
| **فواصل الآيات (Rosettes)** | وردة الآية المصحفية الكلاسيكية (`AyahRosette`) بأطواق وبتلات مذهبة رقيقة وأرقام عربية-مشرقية مدمجة بانسجام تام داخل النص القرآني. |
| **التذييل (Footer)** | فاصل زخرفي دقيق بنواة إسلامية، يليه بيان السورة والمدى الدقيق للآيات (مثل `سورة آل عمران • الآيات ١٩٥–٢٠٠`) مع هوية وِرد الهادئة الرصينة. |

## 3. خوارزمية التجاوب والأبعاد (Responsive Layout & Dimension System)

### أ) الأبعاد الأساسية والنسبة المستهدفة:
- **العرض الثابت للرسم الأساسي**: `1080 px` (المقاس القياسي العالمي لشبكات التواصل والهواتف الذكية).
- **النسبة الأساسية المستهدفة**: **4 : 5** (أي `1080 × 1350 px`).
- **نسبة عرض النص**: يشغل النص القرآني بين **82% إلى 86%** من إجمالي العرض (حوالي **880 إلى 910 px**)، ما يمنع ضيق النص أو امتداده غير المتزن.

### ب) خوارزمية حساب الارتفاع الديناميكي (`ShareLayoutCalculator`):
قبل بناء ويدجت المشاركة، تقوم الخوارزمية بالآتي:
1. قياس الارتفاع الفعلي للنص القرآني المطلوب باستخدام `TextPainter` بدقة على العرض المتاح (`900 px`) مع تضمين فواصل الآيات ومقاييس الخط الفعلي.
2. إضافة ارتفاع الترويسة العلوية، الفواصل، التذييل، والهوامش العلوية والسفلية:
   $$\text{RequiredHeight} = \text{TopPadding} + \text{HeaderHeight} + \text{TextHeight} + \text{FooterHeight} + \text{BottomPadding}$$
3. تحديد الارتفاع النهائي للبطاقة:
   - **نص قصير (1–3 آيات)**: الارتفاع الأدنى هو `1350 px` (الحفاظ الصارم على نسبة 4:5 الذهبية مع توسيط النص رأسيًا بأناقة).
   - **نص متوسط (4–8 آيات)**: يتمدد الارتفاع بحساب منضبط (`1080 × 1500` أو `1080 × 1650` أو `1080 × 1800`) مع ثبات العرض عند `1080 px`.
   - **نص طويل جداً (> 10 آيات أو ارتفاع يتجاوز 2200 px)**: تفعيل خاصية **التقسيم متعدد الصفحات (Multi-Page Sharing)** لتوزيع الآيات على صورتين أو أكثر (1/2، 2/2) بحيث تحافظ كل صفحة على جماليتها المصحفية دون أي ضغط للنص أو تشويه للخط.

## 4. معمارية الكود وتوزيع المكونات (Architecture & Component Design)

سيتم تنظيم نظام المشاركة الجديد داخل حزمة مستقلة ومنظمة:
`lib/features/quran/presentation/widgets/share/`

```
lib/features/quran/presentation/widgets/share/
├── share_layout_calculator.dart     # حاسبة الأبعاد، قياس النصوص، وخوارزمية التقسيم
├── share_border_painter.dart        # رسام الإطار المذهب المزدوج والشرافات الركنية الأربعة
├── share_header_renderer.dart       # رسام رأس السورة المخطوطي والحلية الذهبية
├── quran_text_renderer.dart         # تدفق النص القرآني المتصل وفواصل الآيات
├── share_footer_renderer.dart       # الفاصل الزخرفي، نطاق الآيات، وهوية وِرد
└── quran_share_renderer.dart        # الرسام الموحد عالي الدقة (1080px Canvas)
```

### آلية العرض والمعاينة المستقلة في `QuranShareComposerDialog`:
1. **في شاشة المعاينة للمستخدم (`Live Preview`)**:
   - يتم تغليف `QuranShareRenderer` بـ `FittedBox(fit: BoxFit.contain)` داخل مساحة محددة بأبعاد `Size(1080, calculatedHeight)`.
   - النتيجة: يرى المستخدم على شاشة هاتفه (مهما كان حجمها أو صغرها) معاينة مطابقة 100% بنسبة 4:5 وبنفس التناسب والتفاصيل للوحة الأصلية دون أي تشويه أو تداخل.
2. **عند تصدير ومشاركة الصورة (`Image Generation`)**:
   - يتم استخراج الصورة من الـ `RepaintBoundary` المرتبط بالأبعاد الأصلية `(1080 × calculatedHeight)` مع `pixelRatio: 1.0`.
   - النتيجة: صورة PNG نقية وعالية الدقة بأبعاد `1080 × 1350 px` (أو الارتفاع المحسوب بدقة) خالية من أي اعتماد على دقة شاشة الهاتف أو مقاساته.

## 5. مصفوفة التحقق والاختبار (Acceptance Test Plan)

| الاختبار | المدخلات | النتيجة المتوقعة |
| :--- | :--- | :--- |
| **أ) آية واحدة** | آية الكرسي `2:255` | لوحة بنسبة 4:5 كاملة (`1080 × 1350`)، نص قرآني واسع ومقروء، وردة آية متكاملة، توازن مريح للفراغات. |
| **ب) 3 إلى 5 آيات** | سورة الفاتحة كاملة أو البقرة 1–5 | تكوين 1080 × 1350 متوازن للغاية، هوامش جانبية منضبطة (~83% عرض للنص)، لا يوجد اقتطاع أو تداخل. |
| **ج) آيات آل عمران 195–200** | آل عمران 195–200 | مطابقة تامة لنمط المخطوطة المصحفية، إطار مذهب متناسق، تذييل يعرض `سورة آل عمران • الآيات ١٩٥–٢٠٠`. |
| **د) نطاق ممتد / طويل** | أكثر من 10 آيات | تمدد محسوب للارتفاع أو تقسيم تلقائي لصفحات متعددة دون أي ضغط للخط أو تشويه للأسطر. |
| **هـ) أجهزة بهواتف صغيرة** | شاشات عرضها 320–360px | تظل الصورة المصدرة بأبعاد 1080px القياسية دون أي تأثر بقيود شاشة العرض. |

## 6. خطوات التنفيذ المقترحة

1. إنشاء `ShareLayoutCalculator` لحساب الأبعاد وقياس ارتفاع النص القرآني وضبط النسبة 4:5.
2. إنشاء `ShareBorderPainter` لرسم الإطار المصحفي المذهب المزدوج مع الشرافات والزخارف الركنية الأربعة.
3. إنشاء `ShareHeaderRenderer` لرأس السورة المخطوطي والحلية الجانبية المذهبة.
4. إنشاء `ShareFooterRenderer` للفاصل الزخرفي ومعلومات الآيات وهوية التطبيق.
5. تحديث `QuranShareRenderer` لدمج هذه المكونات بدقة على لوحة 1080px.
6. تحديث `QuranShareComposerDialog` لعرض المعاينة المتناسبة بـ `FittedBox` وتصدير صورة 1080px عالية النقاء.
7. كتابة وتشغيل الاختبارات الآلية للتحقق من الأبعاد ونسبة العرض والارتفاع.
